01 · BACKGROUND

기다리는 문의만으로는 연결이 부족했습니다.

기존 마이프차의 연결은 본사가 브랜드 정보를 올려두면 예비 사장님이 직접 찾아와 문의하는 인바운드 구조였습니다. 브랜드 인지도가 낮을수록 노출과 문의가 부족했고, 예비 사장님 역시 익숙한 브랜드 밖의 선택지를 발견하기 어려웠습니다.

예비 사장님의 관심 지역·업종·예산·연령 등 창업 프로필이 쌓이면서, 이 데이터를 활용해 본사가 먼저 적합한 대상을 찾는 새로운 연결 방식이 가능해졌습니다.

02 · PROBLEM

양면 플랫폼 양쪽에서 미스매치가 발생했습니다.

프랜차이즈 본사
  • 인지도에 따른 노출 격차
  • 문의 발생까지 대기
  • 타깃 대상에게 먼저 도달할 수단 부재
예비 사장님
  • 수많은 브랜드 직접 탐색
  • 비교 기준과 확신 부족
  • 나를 원하는 브랜드와 혜택 확인 어려움

03 · SOLUTION

등록부터 상담 연결까지 하나의 흐름으로 설계했습니다.

개발본부 리더의 “본사가 먼저 창업을 제안한다”는 방향을 바탕으로 파트너·플랫폼·어드민 전체 정책과 화면을 구체화했습니다. MatchUp은 PRO 유료 요금제 전용으로 설계하고, 초기 한식·커피 업종 베타 이후 전체 업종으로 확장했습니다.

본사 제안 등록→AI 대상 매칭→주간 자동 발송→상세 조회→수락·거절→창업 문의 생성
  • 1파트너: 모집 매장·타깃 조건·혜택 입력과 제안 등록
  • 2플랫폼: 제안 목록·상세·응답, 수락 시 창업 문의 자동 생성
  • 3어드민: 제안 검수·제한, 발송·조회·문의 현황과 이력 관리

04 · ITERATION

상담 수집→태그·서비스 분류→건수·추이 분석→원인·영향 정의→개선 우선순위 제안→이후 월 변화 확인

04 · AI AUTOMATION

반복 작성 업무는 자동화하고, 판단과 기획에 더 많은 시간을 썼습니다.

2026년에는 제품 용어집, VOC 분류 기준, 분석 지침, 리포트 구성 템플릿을 하나의 재사용형 AI 스킬로 묶었습니다. 원본 상담 데이터를 넣으면 서비스별 분류와 집계, 비율·추이 계산, 주요 이슈 요약, 시각화가 포함된 HTML 리포트 초안을 같은 기준으로 바로 생성할 수 있도록 구성했습니다.

상담 원본+제품 용어집+분류·분석 지침→AI 스킬 실행→정량 리포트→사람의 검토·해석

AI가 제품 맥락을 임의로 추측하지 않도록 용어와 분류 규칙을 먼저 고정했고, 최종 원인 판단과 개선 우선순위는 직접 검토했습니다. 자동화의 목적은 판단 대체가 아니라 분석 기준의 일관성과 반복 업무 효율화였습니다.

06 · WHAT THIS SHOWS

CX 경험이 서비스 기획 역량으로 이어진 방식

고객의 말을 가장 가까이에서 들은 경험을 기반으로 반복 문제를 구조화하고, 수치로 우선순위를 설명하며, 개선 이후 변화를 다시 확인합니다. 고객 이해와 데이터 해석이 기획의 출발점이 된 과정입니다.

동시에 반복 분석 자체를 도구화해 개인의 노하우를 재사용 가능한 업무 체계로 만들었습니다. 문제 발견부터 개선 기획, 결과 검증, 운영 자동화까지 하나의 제품 루프로 연결하는 서비스 기획자임을 보여주는 사례입니다.
